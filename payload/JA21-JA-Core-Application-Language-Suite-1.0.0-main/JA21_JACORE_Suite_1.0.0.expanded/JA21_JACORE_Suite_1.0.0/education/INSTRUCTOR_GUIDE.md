# Instructor Guide — JA Core Application Language

## Teaching stance

Teach the suite as an evidence-bearing language design and corpus, not as a claim that a production implementation has already passed the modeled tests.

## Assessment

- 20% source and application design
- 20% semantic, type, ownership, effect, and capability reasoning
- 15% AST and compiler-stage reasoning
- 15% runtime, sandbox, and resource reasoning
- 15% R12/MCRT provenance
- 10% diagnostics and recovery
- 5% publication quality and limitation statements

## Five-lens review

Use SOPHIA for semantic review, CHARLOTTE for structure, LANDON for implementation and replay, Professor for learning progression, and Podium for discoverability and evidence presentation.

## Diagnostic teaching

Pair every positive exercise with a negative, boundary, security, or recovery case. Students should explain why the failure belongs to a specific stage and what evidence is safe to emit.

## Capstone gate

A capstone passes only when its source, semantic, AST, R12, runtime, MCRT, validation, and limitations are mutually consistent. Native execution claims require a named implementation, environment, command, output, and retained test evidence.
